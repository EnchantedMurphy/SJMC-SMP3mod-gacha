# Gacha — Fabric 26.3 服务端抽奖模组

仅需服务端安装。使用原版纸券、混凝土展示实体、物品展示实体和烟花，玩家不需要额外客户端模组或资源包。

## 安装与更新

需要 Minecraft Java **26.3**、**Java 25**、Fabric Loader **0.19.5 或更新**和匹配 26.3 的 Fabric API。验证版本为 Fabric API `0.161.0+26.3`。

1. 停服，把 `build/libs/gacha-26.3-fabric-2.0.0.jar` 放入 `mods` 并替换旧 gacha JAR；不要安装 `-sources.jar`。
2. 本版配置格式为 `schemaVersion: 2`，不迁移旧配置。更新时用项目中的 `example-config.json` 覆盖服务器 `config/gacha/config.json`，然后重新设置区域和奖品。全新安装首次启动自动生成同样的配置。
3. 玩家数据写入 `config/gacha/players-v2/`，各池从零开始；旧 `players/` 文件不读取。原版 gacha 抽奖券仍可使用，所有奖池共用同一种单抽券和十连券。
4. 默认货币奖励需要匹配 26.3 的 Fuji，启用 `economy` 并配置 `fuji:coffee_stamp`、`fuji:tongbao`。也可改成普通物品或其他有效指令。
5. 在目标维度执行：

```text
/gacha pool set main 100 64 100 103 66 103
/gacha pool set special 110 64 100 113 66 103
/gacha check main
/gacha check special
/gacha give Steve single 5
/gacha give Steve ten 2
```

投券区域包含两个端点方块，支持相对坐标；同一维度区域不能重叠。后台可以用 `execute in minecraft:overworld run gacha pool set ...` 指定维度。

## 奖池、概率和个人限额

每个池名对应一个独立奖池和投券区域，拥有自己的概率、保底、随机奖励表和固定额外奖励表。创建新池时复制 `poolDefaults` 模板；再次执行 `pool set` 只改变已有池的位置，保留它的奖励设置。修改模板不会改变已创建的池。

每名玩家按 UUID、池名分别累计历史、连续未获 S 的次数和随机奖品获取次数。单抽和十连在同一池内共用计数，换池不会继承保底。删除后重新使用相同池名、或删除后重新加入同等级同奖品 ID 时，已有个人计数仍保留。

| 新池默认规则 | 内容 |
| --- | --- |
| S / A / B 概率 | 2% / 10% / 88% |
| S 保底 | 连续 79 抽未获 S 时，第 80 抽必得 S |
| S 随机奖励 | 重锤 ×1，默认不限次数 |
| S 固定额外奖励 | 咖啡印章余额 +20 |
| A 随机奖励 | 钻石、金锭、铁锭 ×1，等权随机一个 |
| A 固定额外奖励 | 无 |
| B 随机奖励 | 无 |
| B 固定额外奖励 | 铁镐通宝余额 +20 |

十连第十抽始终为 A 或 S。S 保底优先，其次判断自然 S；末抽原本为 B 时改为 A，不提高自然 S 概率。任何 S 都重置本池保底，包括随机表已经耗尽的 S。

每次抽中等级后，先从该玩家仍可获取的随机奖品中按 `weight` 选择一个，再获得这个等级的**全部固定额外奖励**。随机奖品的 `limit` 表示每名玩家最多抽中该奖品多少次，与一次发放的物品数量无关：`-1` 无限、`0` 禁用、正整数为个人次数上限。已抽完的奖品不再参与该玩家的权重计算。十连内部逐抽扣减限额。

随机奖励表为空或所有可抽奖品均耗尽时，只发固定额外奖励；固定表也为空时不发任何奖励，结果显示“无奖励”，仍正常记录等级、历史和保底。固定额外奖励不受随机奖品的限额或权重影响。同一个随机奖品或固定奖励也可以包含多个物品/指令子奖励。

## 动画与轮播展示

- 空闲且所在区块已加载的奖池，在区域顶部上方 2 格展示 S 随机奖励中的物品。使用缩放 0.8 的原版 `item_display`，缓慢旋转，一圈 12 秒，每 4 秒切换一个物品；按配置顺序循环，不展示固定额外物品或纯指令奖励。`limit: 0` 的奖品不展示。
- 轮播是所有玩家共见的奖池展示，不随某名玩家的个人限额消失。未加载区块不会被轮播强制加载。
- 投券后立即隐藏该池轮播；抽奖动画和结果方块清除后恢复。其他池的轮播不受影响。修改、重载、删除池或停服时清理旧模型。
- 默认抽奖动画 100 tick（约 5 秒），混凝土闪动按蓝 88%、黄 10%、红 2% 展示；视觉颜色不决定抽奖结果。单抽 1 个方块，十连上下两排、每排 5 个，从正面看上排左到右，再下排左到右。
- 揭晓后 S/A/B 变成红/黄/蓝，播放最高等级颜色的两侧烟花和音符盒音乐。烟花只产生视觉效果，不伤害玩家或方块。结果默认保留 40 tick（约 2 秒）。
- 玩家同时只能进行一轮，同一池同时只能播放一轮；不同玩家可以在不同池同时抽奖。揭晓后下一轮可以替换尚未清除的上一轮结果。
- 整叠投券只消耗 1 张，其余原样退回；忙碌期间的新券整叠退回原投掷者。抽奖券掉落实体不互相合并。
- 普通纸、投掷器、死亡掉落或发奖溢出掉落不会触发抽奖。背包溢出的奖励在玩家身边掉落，并设置为该玩家的拾取目标。

## 玩家指令

| 指令 | 功能 |
| --- | --- |
| `/gacha`、`/gacha help [页码]` | 分类帮助，管理页按权限开放 |
| `/gacha pool list` | 查看可用池名、区域、维度、朝向 |
| `/gacha history <池名> [页码]` | 该池的三色方块历史 |
| `/gacha history <池名> details [页码]` | 该池的详细历史 |
| `/gacha pity <池名>` | 该池保底与累计抽数 |
| `/gacha pending <池名>` | 该池待领取和异常奖励 |

方块历史按时间从左到右、从下到上由早到晚排列，每行最多 20 个方块。出红后标注本次出红抽数并结束该行，后续记录从上面一行最左边继续。每页约 100 抽，保持完整行，最多多 19 抽；只有全历史最新一行可能未满 20 个且未出红。详细历史每页 10 抽、最新在前，保留奖品、时间和距上次 S 的逐抽计数。

两种视图可翻页或切换，按钮始终携带当前池名；服务端只读取实际点击者的 UUID，不接受客户端指定玩家。时间按北京时间显示，保留简洁的历史样式。

## 管理指令

OP 2 级或后台可用：

| 指令 | 功能 |
| --- | --- |
| `/gacha give <玩家或选择器> single [数量]` | 发通用单抽券，数量默认 1 |
| `/gacha give <玩家或选择器> ten [数量]` | 发通用十连券 |
| `/gacha pool set <池名> <坐标1> <坐标2>` | 创建池或更新已有池区域 |
| `/gacha pool facing <池名> +x或-x或+z或-z` | 设置面朝方向，两侧烟花随之调整 |
| `/gacha pool remove <池名>` | 删除池，不删除个人历史计数 |
| `/gacha reward list <池名>` | 列出随机奖品及个人限额 |
| `/gacha reward sethand <池名> S或A或B <ID> [权重] [限额]` | 保存主手整叠物品和完整组件；默认权重 1、限额 -1 |
| `/gacha reward limit <池名> S或A或B <ID> <次数>` | 修改个人限额，已有获取次数保留 |
| `/gacha reward remove <池名> S或A或B <ID>` | 删除随机奖品，允许清空等级 |
| `/gacha bonus list <池名>` | 列出固定额外奖励 |
| `/gacha bonus sethand <池名> S或A或B <ID>` | 保存固定额外物品 |
| `/gacha bonus remove <池名> S或A或B <ID>` | 删除固定额外奖励 |
| `/gacha check <池名> [在线玩家]` | 验证该池全部物品和奖励指令；后台需指定玩家 |
| `/gacha pending <池名> <在线玩家>` | 查看该池指定玩家的待领/异常动作 |

`sethand` 不消耗主手物品；同一表、同等级同 ID 会替换奖品。附魔、名称、潜影盒内容等完整组件均保留。修改正在抽奖的池时需等本轮揭晓。

OP 4 级可用：

```text
/gacha reward setcommand <池名> S|A|B <ID> <名称> <完整指令>
/gacha bonus setcommand <池名> S|A|B <ID> <名称> <完整指令>
/gacha reload
/gacha recover <池名> <在线玩家> <记录UUID> <动作序号> retry|done
```

`setcommand` 在游戏内执行以验证玩家上下文；名称有空格时加双引号，指令不带 `/`，支持 `%player%`、`%uuid%`。指令以后台身份在中奖玩家的位置和维度执行，`@s` 仍是后台。例如：

```text
/gacha bonus setcommand main S stamps "咖啡印章 ×20" economy give %player% fuji:coffee_stamp 20
/gacha reward limit main S mace 1
```

随机指令奖品的限额用 `reward limit` 设置。发券、帮助、重载属于全局操作，不需要池名；与奖池相关的查询、奖品管理和恢复均指定池名。

## 配置与数据

```text
config/gacha/
├── config.json
└── players-v2/
    └── <玩家UUID>.json
```

完整默认配置见 [example-config.json](example-config.json)。`poolDefaults` 为新池模板，实际池写在 `pools.<池名>` 中，结构如下：

| 字段 | 含义 |
| --- | --- |
| 顶层 `schemaVersion` | 本版必须为 2 |
| 顶层 `animationTicks`、`resultTicks` | 动画 20–1200 tick，结果 0–1200 tick |
| 池 `dimension`、`minX/Y/Z`、`maxX/Y/Z` | 所在维度及投券区域，单边最多 65 格 |
| 池 `displayFacing` | `+x/-x/+z/-z`，默认 +z |
| 池 `sProbability`、`aProbability` | 非负绝对概率，总和不超过 1；B 为剩余概率 |
| 池 `pity` | 1–1000000 的 S 保底抽数 |
| 池 `rewards.S/A/B` | 随机奖品数组，各等级都需提供，可为空 |
| 池 `fixedRewards.S/A/B` | 固定额外奖励数组，各等级都需提供，可为空 |
| 奖品 `id`、`label` | ID 在同一表同等级内唯一，1–64 位字母数字、下划线或短横线；label 为结果与历史名称 |
| 随机奖品 `weight`、`limit` | 正整数权重；个人获取次数上限，-1 无限、0 禁用 |
| 奖品 `rewards` | 非空子奖励数组，每项仅包含 `item` 或 `command` 之一 |

物品子奖励：`{"item":{"id":"minecraft:diamond","count":3}}`。货币子奖励：`{"command":"economy give %player% fuji:coffee_stamp 20"}`。Fuji 货币标识是经济账户 ID，不是物品注册 ID；实体货币道具请用 `sethand` 保存。

修改文件后执行 `/gacha reload`。重载失败保留当前生效配置；已开始的抽奖使用确定并保存的结果与奖励快照，不受之后的奖励表修改影响。

## 领取、异常和商店

开始抽奖时先保存本轮结果、个人限额、保底和历史，再移除投券实体；投掷实体 UUID 防止重复处理。断线后结果仍确定，重连继续发奖；死亡期间暂存，复活后发放。正常停服在玩家断开前完成可发动作，并清理全部展示实体。

每项子奖励状态为 `READY`、`SENDING`、`DONE`、`FAILED`。执行前保存 `SENDING`；崩溃或外部指令失败产生的不确定动作不自动重试。管理员核实背包/余额后用 `recover ... done` 标记已发，或用 `recover ... retry` 重试确认未发的动作。恢复时校验领取记录属于指定池。随机奖品限额按已确定的结果计数，恢复发奖不会再次扣减。

玩家文件损坏时停止该玩家抽奖和发奖，保留原文件，不静默重置。备份服务器时同时备份 `config/gacha`、世界玩家数据和 Fuji 经济数据；原版背包与外部经济存储不能作为一个跨系统原子事务提交。

商店购买后以后台身份执行 `gacha give <商店玩家名占位符> single 1` 或 `gacha give <商店玩家名占位符> ten 1`。商店复制物品时必须保留 `minecraft:custom_data`；只有显示名称不能生成有效券。

## 开发与验证

```text
gradlew.bat build
```

构建运行 JUnit 和 Fabric 服务端游戏测试。验证概率和保底、十连个人限额、空奖励、奖励快照、按玩家/奖池独立存储、历史分页和原版点击包、物品轮播旋转/切换/清理、抽奖与结果期间隐藏、其他池继续展示、四种朝向、退券、断线重连、死亡暂存和背包溢出。游戏测试使用 `build/run/gameTest` 内的独立新版配置。

Fuji 14.12.0 的真实专用服务器集成测试：把其官方 26.3 JAR 放在 `integration/` 中，执行：

```powershell
.\integration\run-fuji-test.ps1 -Offline
```

测试服只监听本机临时端口，数据位于 `build/run/fujiIntegration`。验证重锤随机奖励、固定咖啡印章 +20、B 固定铁镐通宝 +20，结果写入 `fuji-test-result.json`。普通构建不加载 Fuji；生产包不包含测试入口或服务器数据。声音听感、客户端模型大小和动画流畅度仍需进服人工验收。
