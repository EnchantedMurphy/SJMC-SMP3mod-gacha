# Gacha — Fabric 26.3 服务端抽奖模组

只需安装在服务端，玩家客户端不需要本模组或资源包。抽奖券使用带专用 `custom_data` 标记的原版纸；动画使用原版 `block_display` 和烟花网络效果，不添加自定义物品、实体类型或客户端协议。

## 简单操作说明

### 普通玩家

**操作：** 从管理员或商店获取抽奖券后，将券投掷到抽奖池内。**效果：** 等待约 5 秒后获得奖品；单抽券抽 1 次，十连券抽 10 次。整叠投入只消耗 1 张，余券退回。

| 操作 | 效果 | 示例 |
| --- | --- | --- |
| 查看帮助 | 查看玩法和个人查询指令 | `/gacha help` |
| 查看抽奖历史 | 蓝／黄／红方块表示 B／A／S，每页约 100 抽，按完整行分页、每行最多 20 抽；出红后标注本轮抽数并换行，可翻页或点击详细历史 | `/gacha history`，也可用 `/gacha history 2` 直接查看第 2 页 |
| 查看剩余保底抽数 | 显示连续未获S的抽数、最多再抽多少次必得S和累计抽数 | `/gacha pity` |
| 查看待领取奖励 | 列出待发放或异常记录，正常待领奖励会自动继续发放 | `/gacha pending` |

### OP 管理

以下常用操作需要 OP 2 级。把示例里的 `Steve` 换成实际玩家名，坐标换成自己的奖池位置。

| 操作 | 效果 | 示例 |
| --- | --- | --- |
| 设置抽奖池 | 在当前维度用两个角确定投券区域，包含端点方块 | `/gacha pool set main 100 64 100 103 66 103` |
| 发单抽券 | 给玩家指定数量的单抽券 | `/gacha give Steve single 5`：发 5 张 |
| 发十连券 | 每张对应 10 抽，数量指券数 | `/gacha give Steve ten 2`：发 2 张，可抽 20 次 |
| 查看或删除奖池 | 查看所有奖池，或删除指定奖池 | `/gacha pool list`；`/gacha pool remove main` |
| 调整展示方向 | 设置面朝 +x、-x、+z 或 -z；从正面看十连按上排左至右、下排左至右排列 | `/gacha pool facing main +z` |
| 保存主手奖品 | 保存主手整叠物品及组件，不消耗物品；同等级同 ID 会替换原奖品 | 手持 3 个钻石后执行 `/gacha reward sethand A diamond 1`：该奖品发 3 个钻石，权重为 1 |
| 查看或删除奖品 | 查看等级、ID、权重，或删除指定奖品；每个等级须至少保留一个 | `/gacha reward list`；`/gacha reward remove A diamond` |
| 检查奖池配置 | 检查物品数据和奖励指令是否能解析 | `/gacha check Steve` |
| 查看玩家领取记录 | 检查指定在线玩家的待领或异常奖励 | `/gacha pending Steve` |

指令奖品和重载配置需要 OP 4 级；高级异常恢复步骤见后面的“指令”和“断线、停服与异常领取”。

| 操作 | 效果 | 示例 |
| --- | --- | --- |
| 保存指令奖品 | 游戏内执行，将后台指令设为奖品；`%player%` 会替换为中奖玩家名 | `/gacha reward setcommand B tongbao "铁镐通宝 ×20" economy give %player% fuji:tongbao 20` |
| 重载配置 | 使修改后的配置文件生效，已开始的抽奖继续使用原结果 | `/gacha reload` |

### config 配置

先启动一次服务器，再编辑 **服务器目录中的 `config/gacha/config.json`**。下列示例是在已有 JSON 中修改对应字段；保存后执行 `/gacha reload`（OP 4 级）。

| 操作 | 效果 | 示例 |
| --- | --- | --- |
| 调整 S、A 概率 | 数值范围为 0–1，两者总和不能超过 1；B 使用剩余概率 | `"sProbability": 0.02, "aProbability": 0.10`：S 2%、A 10%、B 88% |
| 调整 S 保底 | 连续未获S时，第指定抽数必得S；任意S都会重置计数 | `"pity": 80`：第 80 抽必得S |
| 调整动画与结果展示时长 | 数值单位为 tick，正常情况下 20 tick 约为 1 秒 | `"animationTicks": 100, "resultTicks": 40`：约 5 秒动画、2 秒结果展示 |
| 修改奖池展示方向 | 编辑 `pools` 中相应奖池的 `displayFacing`，可填 `+x/-x/+z/-z`；区域坐标建议用上面的 OP 指令设置 | `"displayFacing": "+z"`：面朝 Z 正方向，横排沿 X 轴 |
| 修改奖品、名称或权重 | 编辑 `rewards.S/A/B` 中的奖品；同等级按权重随机选一个奖品 | `"label": "钻石 ×3", "weight": 2`：显示该名称，权重设为 2 |
| 设置物品子奖励 | 指定物品 ID 和一次发放数量 | `{"item": {"id": "minecraft:diamond", "count": 3}}`：发 3 个钻石 |
| 设置 Fuji 货币子奖励 | 通过 Fuji 后台指令增加中奖玩家的货币余额 | `{"command": "economy give %player% fuji:coffee_stamp 20"}`：咖啡印章余额 +20 |
| 设置组合奖品 | 同一个奖品的 `rewards` 数组中放多项子奖励，中奖时一起发放 | `"rewards": [{"item": {"id": "minecraft:mace", "count": 1}}, {"command": "economy give %player% fuji:coffee_stamp 20"}]`：同时获得重锤和 20 咖啡印章 |

每个等级至少保留一个奖品。Fuji 货币奖励需要服务器安装 Fuji、启用 `economy` 并配置对应货币。完整默认结构见 `example-config.json`，字段范围见后面的“配置与数据”。

## 安装与开始使用

需要 Minecraft Java **26.3**、**Java 25**、Fabric Loader **0.19.5 或更新**，以及匹配 26.3 的 Fabric API。构建验证使用 Fabric API `0.161.0+26.3`。

1. 把 `build/libs/gacha-26.3-fabric-1.1.3.jar` 放入服务器 `mods` 文件夹。不要安装 `-sources.jar`。
2. 使用默认货币奖品时，安装匹配 26.3 的 Fuji，启用其 `economy` 模块，并保留您已配置的 `fuji:coffee_stamp` 和 `fuji:tongbao` 货币。
3. 启动服务器，自动生成 `config/gacha/config.json`。本版使用全新的 gacha 券与数据，不识别旧版 lottery 券，也不读取或迁移 `config/lottery/`。
4. 在抽奖池所在维度执行以下指令，把示例坐标替换为实际区域：

```text
/gacha pool set main 100 64 100 103 66 103
/gacha check
/gacha give 玩家名 single 1
/gacha give 玩家名 ten 1
```

向设置的区域内投掷一张抽奖券即可抽奖。区域包含两个端点方块，坐标顺序可颠倒，也支持 `~` 相对坐标。后台指定维度可用：

```text
execute in minecraft:overworld run gacha pool set main 100 64 100 103 66 103
```

## 默认规则与奖品

| 项目 | 默认设置 |
| --- | --- |
| S 级概率 | 2% |
| A 级概率 | 10% |
| B 级概率 | 88% |
| S 级保底 | 第 80 抽 |
| S 级测试奖品 | **同时获得重锤 ×1 和咖啡印章余额 +20** |
| A 级测试奖品 | 钻石 ×1、金锭 ×1、铁锭 ×1 中等概率随机一个 |
| B 级测试奖品 | 铁镐通宝余额 +20 |

每个玩家按 UUID 独立累计连续未获 S 的抽数，单抽与十连共用计数。获得自然 S 或保底 S 后立即归零，随后继续逐抽累计。连续 79 抽未获 S 时，第 80 抽必得 S。

十连的第十抽始终为 A 或 S，即使前九抽已经获得 A/S。先判断 S 保底与自然 S；如果末抽原本为 B，改为 A，不提高末抽的自然 S 概率。每次抽中某个等级后，根据该等级奖品的 `weight` 权重选择一个奖品；一个奖品可以包含多项子奖励。

## 动画与投券行为

- 默认播放 100 tick（正常 TPS 下约 5 秒）的原创音符盒竖琴/铃铛旋律，不需要自定义音乐文件。
- 区域顶部上方 2 格出现边长 0.6 格的混凝土展示实体，颜色只在蓝、金（黄色混凝土）、红之间随机变化。单抽显示 1 个，十连显示上下两行，每行 5 个；顺序为上排左至右，再下排左至右。
- 结果揭晓时，S/A/B 分别变为红/黄/蓝混凝土；左右两侧播放本次最高等级颜色的原版烟花爆炸及音效。烟花仅为视觉效果，不伤害玩家或方块。
- 同时发放奖品，聊天中每个奖项的文字分别使用 S 红、A 黄、B 蓝。默认结果再展示 40 tick（约 2 秒），随后清除。下一轮可以立即开始，新动画会替换旧结果展示。
- 同一玩家同时只能进行一轮，同一抽奖池同时只播放一轮；多个不重叠的抽奖池可以分别进行抽奖。
- 忙碌期间投入的新券整叠消失并退回原投掷玩家。整叠投券正常启动时只消耗 **1 张**，剩余券退回，不连续触发多轮。
- 未设置区域的投券、普通纸、仅在铁砧改名的纸、投掷器/死亡掉落/奖励溢出产生的无投掷者物品均不触发抽奖。抽奖券掉落实体不互相合并，避免两名玩家投券后归属混淆。
- 背包放不下的物品在玩家身边掉落，并设置为该玩家的拾取目标；不会覆盖原物品，也不会因返还券位于抽奖池而再次抽奖。普通掉落物仍受游戏中的消失、环境和其他模组行为影响。

## 指令

普通玩家：

| 指令 | 功能 |
| --- | --- |
| `/gacha` 或 `/gacha help [页码]` | 按个人、券与池、奖品、高级管理分类查看帮助；管理页只向有权限的人开放 |
| `/gacha history [页码]` | 三色方块历史，从左到右、从下到上按时间由早到晚排列，每页约 100 抽，按完整行分页、每行最多 20 抽；出红后标注抽数，后续抽奖从上面一行最左边继续 |
| `/gacha history details [页码]` | 原版详细历史，每页 10 抽，显示奖品、逐抽计数、北京时间和奖池；可翻页或返回方块历史 |
| `/gacha pity` | 连续未获 S 的次数、距离必得 S 的最大抽数、累计抽数；文字黄色、数字橙色 |
| `/gacha pending` | 查看待领取或异常奖励；正常待领动作会在下一秒继续处理 |

方块历史使用蓝／黄／红 `■` 分别表示 B／A／S，按时间从左到右、从下到上由早到晚排列。每行最多 20 个方块，遇到红色方块时在后面标注本次出红花费的抽数并结束该行；后续抽奖从上面一行的最左边继续。先按全部历史生成行，再从最近记录开始分页，每页约 100 抽；达到目标抽数时保留整行，因此最多可多出 19 抽。只有全历史最新一行可以尚未满 20 个且未出红。后面的页码展示更早的记录。详细历史仍最新在前，其中“距上次S第N抽”记录每一抽在本轮保底计数中的位置：首次从 1 开始，获得任意S后，下次重新从 1 计数；获S的当抽显示获得该S花费的抽数。此计数跨页连续，不显示S保底或十连末抽保底标记。两种历史各有翻页按钮；点击“详细历史”从当前方块页最新一抽起查看详情，点击“方块历史”返回包含当前详细记录的方块页。历史及帮助按钮使用原版 `custom` 点击事件，直接请求服务端显示页面，无执行命令确认框。

OP 2 级或后台：

| 指令 | 功能 |
| --- | --- |
| `/gacha give <玩家或选择器> single [数量]` | 发放单抽券；数量为券数，默认 1 |
| `/gacha give <玩家或选择器> ten [数量]` | 发放十连券；每张券对应 10 抽 |
| `/gacha pool set <池名> <坐标1> <坐标2>` | 设置当前维度的长方体区域 |
| `/gacha pool list` | 列出区域及维度 |
| `/gacha pool remove <池名>` | 移除区域 |
| `/gacha pool axis <池名> x或z` | 设置十连横排方向，默认 x |
| `/gacha pool facing <池名> +x或-x或+z或-z` | 设置展示面朝方向，默认 +z；也支持使用 `pool axis` 后接这四种方向 |
| `/gacha reward list` | 列出全部等级的奖品、ID 和权重 |
| `/gacha reward sethand S或A或B <奖品ID> [权重]` | 保存主手整叠物品及完整组件，包括名称、附魔、Fuji 自定义数据等 |
| `/gacha reward remove S或A或B <奖品ID>` | 删除一个奖品；不允许删空某个等级 |
| `/gacha check [在线玩家]` | 验证奖品物品数据与指令解析；后台需指定玩家 |
| `/gacha pending <在线玩家>` | 查看该玩家领取异常 |

旧配置未设置 `displayFacing` 时仍读取 `displayAxis`：`x` 对应面朝 `+z`，`z` 对应面朝 `-x`，保持原来实体的排列顺序。已有 `pool axis ... x/z` 指令继续有效，并清除显式朝向。设置新朝向时两侧烟花也随横排调整。

`sethand` 不消耗主手物品。同等级存在相同 ID 时替换该奖品，否则添加。它会保存整个物品：主手为潜影盒时，奖品为带原内容的潜影盒。

OP 4 级或后台：

```text
/gacha reward setcommand S|A|B <奖品ID> <名称> <完整奖励指令>
/gacha reload
/gacha recover <在线玩家> <记录UUID> <动作序号> retry|done
```

`setcommand` 需游戏内管理员执行以验证目标玩家上下文；名称包含空格时用双引号。指令不带开头的 `/`，支持 `%player%` 和 `%uuid%`。例如：

```text
/gacha reward setcommand B tongbao "铁镐通宝 ×20" economy give %player% fuji:tongbao 20
```

定义后台奖品指令和重载文件需要 OP 4 级，防止低权限管理员通过奖品指令获得更高权限。奖品指令以后台身份、中奖玩家的位置和维度执行；`@s` 仍为后台，应使用占位符指定玩家。

## 配置与数据

服务器目录下自动创建：

```text
config/gacha/
├── config.json          # 概率、保底、展示时长、区域与奖品
└── players/
    └── <玩家UUID>.json  # 个人保底、全部历史与逐项领取状态
```

完整默认配置见项目里的 `example-config.json`。修改服务器中的配置后执行 `/gacha reload`。重载失败时保留当前已生效配置和原文件；已开始的抽奖始终使用事先确定并保存的结果及奖品快照。

| 字段 | 含义与范围 |
| --- | --- |
| `sProbability`、`aProbability` | 0–1 的绝对概率；2% 填 `0.02`，两者总和不超过 1 |
| `pity` | 1–1000000 的正整数 |
| `animationTicks` | 20–1200 tick；默认 100 |
| `resultTicks` | 0–1200 tick；默认 40；烟花会至少保留必要的几 tick |
| `pools` | 以池名为键的区域；单边最多 65 格，同一维度不可重叠 |
| 奖池 `displayFacing` | 可选，面朝 `+x/-x/+z/-z`；优先于旧字段 `displayAxis` |
| `rewards.S/A/B` | 每个等级均需至少一个奖品 |
| 奖品 `id` | 同等级内唯一，1–64 位字母数字、下划线或短横线 |
| 奖品 `label` | 历史与结果消息显示名称 |
| 奖品 `weight` | 正整数权重，默认 1；例如 3 和 1 分别占本等级 75% 与 25% |
| 奖品 `rewards` | 一次中奖同时发放的子奖励列表；每项仅有 `item` 或 `command` 之一 |

普通物品子奖励示例：

```json
{"item": {"id": "minecraft:diamond", "count": 3}}
```

Fuji 货币子奖励示例：

```json
{"command": "economy give %player% fuji:coffee_stamp 20"}
```

Fuji 的这两个 ID 是经济账户的货币标识，不是原版物品注册 ID，所以默认直接增加余额。如需实体货币道具，用 `sethand` 保存实际道具。此方式无需给本模组添加 Fuji 编译依赖。[Fuji 官方经济模块实现](https://github.com/fuji-fabric/fuji/blob/38824a5371/fabric/src/main/java/mod/fuji/module/initializer/economy/EconomyInitializer.java)。

## 接入其他模组的商店

商店在玩家购买后，以后台身份执行：

```text
gacha give <该商店的玩家名占位符> single 1
gacha give <该商店的玩家名占位符> ten 1
```

把 `<该商店的玩家名占位符>` 替换为商店文档规定的占位符。商店支持保存主手商品时，也可以先领取一张抽奖券，再将完整物品设为商品；商店必须保留 `minecraft:custom_data` 组件。仅保存纸的显示名称无法生成有效券。普通玩家不需要发券指令权限。

## 断线、停服与异常领取

开始时先保存本轮全部结果、保底变化和历史，再移除投掷实体。记录投掷实体 UUID，使旧掉落实体在重启后再次出现时不会重复生成一轮。玩家断线时，结果照常确定，未发放奖励保留；重连后自动领取。死亡期间暂存奖励，玩家复活后再领取。正常停服会在玩家断开前完成可发放动作，并清除展示实体。

每项子奖励有 `READY`（未发放）、`SENDING`（开始发放）、`DONE`（完成）、`FAILED`（异常）状态。执行前先保存 `SENDING`；发生崩溃或外部指令异常时，不自动重试不确定动作，避免重复发奖。管理员核实后用 `recover ... done` 标记已发放，或用 `recover ... retry` 重试已确认未发放的动作。

玩家文件损坏时拒绝该玩家的抽奖与发奖，不把历史或保底静默重置。使用原版背包保存和外部货币指令，因此无法让三个独立存储系统在断电时保持一个原子事务；遇到异常状态需核对背包和 Fuji 余额后恢复。备份服务器时同时备份 `config/gacha`、世界玩家数据和 Fuji 经济数据。

包含 JUnit 测试与 Fabric 服务端游戏测试。游戏测试覆盖真实玩家投掷、单抽/十连实体、三色动画、四种面朝方向与两侧烟花、整叠余券退回、忙碌退券、组合奖励、独立玩家数据、实际详细历史切换与翻页点击包、历史隐私与帮助权限、断线重连、死亡暂存和背包溢出。单元测试另验证历史逐抽计数、每行20方块、跨页出红计数、切换页码、文字颜色、旧方向配置兼容、点击数据编码与非法参数。此前版本已通过 Fuji `14.12.0` 的真实专用服务器入账测试。生产 JAR 只包含 `src/main`；测试入口、Fuji 测试依赖和测试服务器数据不在其中。

```powershell
.\integration\run-fuji-test.ps1 -Offline
```

测试服只监听本机的临时端口，数据全部在 `build/run/fujiIntegration/`。它启用隔离的两个测试货币，实际投券验证重锤、咖啡印章 +20 和铁镐通宝 +20；结果保存到 `fuji-test-result.json`。普通构建不需要下载或加载 Fuji。

Minecraft 的 GameTest 模拟用户名服务与 Fuji 的经济指令不兼容，所以真实货币验证采用普通 Dedicated Server。服务端测试验证展示实体与原版网络效果的创建、颜色及清理；音乐听感和客户端实际画面仍需进服人工验收。
